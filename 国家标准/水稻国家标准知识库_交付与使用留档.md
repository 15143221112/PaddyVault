## 五、漏召回根因与应对（重点）

### 5.1 现象
跨主题复合提问（如"热害+冷害+储存+种子"一次问）时，离题远的标准（如种子 GB 4404.1）会被漏召回，模型误报"知识库未收录"。

### 5.2 根因（已实证）
- WeKnora 快速问答把整句话当一个 query 做**一次**检索，返回 topK 片段；
- 多主题 query 被向量/BM25 语义平均化，topK 偏向语义重心，离题远的标准被挤出候选；
- 单独问同一个问题时能完整召回 → 证实不是入库/过滤问题，是**单 query 单检索的候选容量局限**。

### 5.3 是不是 WeKnora 的问题
一半是。这是**单轮单 query RAG 的普遍局限**（所有同类平台都有），非 WeKnora 独有；但 WeKnora 默认走"快速问答"路径、未自动拆解 query，放大了该局限。

### 5.4 为什么"豆包/agent"多问题不漏
豆包是 agent 编排，收到多问题会**主动拆解成多个子任务，每个子问题单独检索再合并**（多 query 多次检索），故不漏。这正是大厂 Agentic RAG 的做法。

### 5.5 应对方案（按优先级）

**① 使用层（立即生效）**：**一题一问**。涉及不同主题时不要堆一起问。

**② 换问答模式**：WeKnora 用**智能推理（ReAct Agent）**模式而非快速问答——它多步推理、多次检索，天然拆解多问题，是最直接的大厂做法。

**③ 扩大候选**：智能体检索设置把 **TopN 候选数调到 8~10**、重排取前 K 同步加大、相似度阈值适当降到 0.2 附近。

**④ 主流/大厂做法（长期优化方向）**：
| 做法 | 说明 | 大厂应用 |
|---|---|---|
| Query 拆解（Decomposition） | LLM 先把多问题拆成多个独立子 query，逐条检索合并 | 通用 RAG 标配 |
| Agentic 多步检索（ReAct） | 规划→检索→行动循环，每步一次检索 | 豆包/大模型 Agent、OpenAI 深度研究等 |
| 扩大召回池 + 重排 | 先召回 top20~50，重排后再取前K，避免提前截断 | 主流 RAG 框架 |
| 意图识别/路由 | 先判 query 意图，路由到对应知识库/检索策略 | WeKnora 内置（默认未充分启用） |
| 混合检索权重调优 | 平衡向量+BM25 融合权重，避免单一召回偏 | 通用 |

## 六、使用指南

1. **问答务必一题一问**（尤其跨主题），这是最有效的防漏方法；
2. 追求长/复合问题可用**智能推理 Agent 模式**；
3. 单独提问即可获得：结论 + 定义 + 分级表格 + 检验方法 + 溯源 + 防幻觉边界说明；
4. 复杂指标核对时，可追问"引用了哪些标准/表号"再回查原文；
5. 如需复合提问不遗漏，去智能体检索设置调大 TopN（见 5.5③）。
